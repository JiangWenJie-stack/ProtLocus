# Rescue DP 候选初筛实验技术报告

日期：2026-09-11  
适用代码：`ProtLocus 1.0.0`  
实验状态：**结论否定，实验实现已全部回滚，不进入发布版本**

---

## 1. 摘要

本轮实验验证了下面这条加速路径：

```text
无可信 anchor 的 rescue 候选
  -> 廉价初筛
  -> 低潜力候选直接丢弃
  -> 高潜力候选执行原有端点延伸和完整 DP
```

实验依次测试了局部无 gap BLOSUM 分数、chain 排名、query 级重试、低置信度级联重试、seed 覆盖度、anchor 密度，以及固定预算 mini-DP。结论是：

> **在保持当前 PAF 输出稳定的要求下，已测试的初筛信号没有可用的工作点。**

- 严格 BLOSUM 阈值 30 可拒绝约 33.0% 的 rescue 候选，并获得 1.37 倍整体提速，但四个基因组合计丢失 31 条 query，另有 26 条 query 的最佳分数下降。
- 将阈值降到 20 虽然不再丢 query，却只能拒绝约 1.36% 的候选，整体仅提速 1.043 倍，而且仍改变 11 条 query 的最佳位点。
- 固定保留高排名候选或按分数重试都不能找回远缘弱同源；扩大重试预算只会逐步重新执行被省掉的 DP。
- 低置信度级联可恢复最佳分数和位点，但恢复到零变化时，整体提速仅剩 1.004 倍，等同于没有实际收益。
- 固定预算 mini-DP 比简单 BLOSUM 更贵，但在保留全部已输出记录时最多只能安全拒绝约 3.04% 的候选；其观测开销本身已占 `align_s` 的约 1.63%，预计净收益不超过约 1%，处于运行波动范围内。

因此，本轮候选初筛方案没有合入默认配置，也没有保留为实验参数。生产代码已恢复到实验前、经过四基因组验证的实现。

---

## 2. 背景与问题定义

`--accuracy` 模式会救援 refine 后没有可信 anchor 的候选。上游 miniprot 会直接丢弃这类候选，而本项目会对其执行有界 DP，以找回重复区域、旁系同源区域和远缘弱同源中的真实命中。

在本次四基因组数据中，共观察到 282,018 个 rescue 候选：

| 基因组 | Rescue 候选数 |
| --- | ---: |
| 小鼠 mouse | 57,308 |
| 大鼠 rat | 52,369 |
| 非洲爪蟾 frog | 91,454 |
| 斑马鱼 zebrafish | 80,887 |
| **合计** | **282,018** |

这些候选是 `--accuracy` 模式的主要新增工作量。初筛假设是：如果能在昂贵 DP 之前识别明显无望的候选，就可以在不影响有效弱同源命中的前提下减少 `align_ext_s` 和完整 DP 的计算量。

### 2.1 验收标准

实验采用逐级收紧的四层标准：

1. **映射召回稳定**：baseline 已映射的 query 不能变为未映射。
2. **最佳命中稳定**：每条 query 的最佳 `AS:i` 分数和最佳基因组位点不能改变。
3. **完整输出稳定**：每条 query 的全部 PAF 记录不能改变，包括次级命中及其主次关系。
4. **收益足够大**：扣除初筛本身的成本后，整体 wall time 必须有稳定、可复现的下降。

仅满足第 1 层并不足以作为默认优化，因为初筛还可能改变最佳位点、次级同源拷贝和候选间的排序关系。

## 3. 实验设计

### 3.1 数据与运行参数

- Query：`Test_realdata/all_queries.fa`，共 1,114 条蛋白。
- 目标基因组：mouse、rat、frog、zebrafish 四个真实基因组。
- 运行参数：`-I -u -t56 --accuracy --profile`。
- 首轮阈值扫描使用 3 次重复的中位数；后续策略探针使用 1 次运行。
- 所有速度比较只在同一批实验的 baseline 与候选配置之间进行，不跨批次直接比较 wall time。

### 3.2 第一版廉价分数

初筛仅作用于“无可信 anchor、准备进入 rescue DP”的候选。对 refine anchor 做均匀采样，并计算包含 5-mer seed 的局部无 gap BLOSUM 最佳分数：

- 每个候选最多采样 16 个 anchor；
- 每个 anchor 左右各检查最多 24 个氨基酸；
- 默认上界为 `16 * (5 + 2 * 24) = 848` 次残基/密码子打分；
- 无法可靠打分的边界情况保守放行；
- 初筛发生在剪接证据提取、左右端点延伸和完整 DP 之前。

该实现的目标不是替代 DP，而是只过滤明显不可能成功的候选。

### 3.3 后续增强信号

在单一分数失败后，又依次加入或分析了以下安全机制：

- 按现有 chain 排名固定保留前 K 个低分候选；
- 当 query 没有输出时，按初筛分数从高到低重试被拒候选；
- 当最佳输出 `AS` 仍较低时继续级联重试；
- chain 分数、无 gap 分数、anchor 数、各特征排名；
- DP 前 seed query 覆盖度、seed nt span、anchor 密度；
- 固定窗口、只计分、不生成 CIGAR 的 splice-aware mini-DP。

## 4. 实验结果

### 4.1 严格 BLOSUM 阈值扫描

四个基因组的同批 baseline wall time 合计为 92.901 秒。下表为四基因组汇总结果：

| 阈值 | 候选拒绝率 | Wall time | 提速 | 丢失 query | 最佳分数下降 | 最佳位点改变 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 20 | 1.36% | 89.038 s | 1.043x | 0 | 1 | 11 |
| 30 | 33.04% | 67.943 s | 1.367x | 31 | 26 | 56 |
| 40 | 82.46% | 29.106 s | 3.192x | 214 | 159 | 249 |
| 50 | 97.59% | 17.815 s | 5.215x | 852 | 204 | 272 |

阈值 20 基本保持召回，但过滤量太小，且输出并不稳定。阈值 30 首次产生有意义的速度收益，却立即丢失 31 条 query：mouse 4 条、frog 9 条、zebrafish 18 条。阈值继续提高后，召回损失迅速恶化。

这一步已经否定了“使用单一绝对局部分数直接过滤”的方案。被过滤掉的不是一小撮异常值，而是 rescue 机制本来要恢复的弱同源主体。

### 4.2 固定保留 chain 排名前 K 个候选

为避免低分真命中被直接丢弃，实验让每条 query 的前 K 个低分候选绕过初筛。四基因组同批 baseline 为 82.201 秒。

| K | 有效拒绝率 | Wall time | 提速 | 丢失 query |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 31.78% | 62.711 s | 1.311x | 31 |
| 2 | 30.58% | 65.599 s | 1.253x | 31 |
| 4 | 28.29% | 67.879 s | 1.211x | 29 |

即使保留前 4 个候选，也只恢复 2 条 query，却明显消耗了速度收益。说明真实弱命中通常不在低分候选的 chain 前列，chain 排名不能作为可靠的安全阀。

### 4.3 Query 无输出后按初筛分数重试

下一版不再固定保留候选，而是在 query 没有输出时，对被拒候选按初筛分数从高到低重跑完整流程。四基因组同批 baseline 为 87.663 秒。

| 每条 query 最大重试数 | Wall time | 提速 | 丢失 query |
| ---: | ---: | ---: | ---: |
| 4 | 66.128 s | 1.326x | 28 |
| 8 | 64.696 s | 1.355x | 23 |
| 16 | 72.404 s | 1.211x | 15 |

增加到 16 次重试后仍有 15 条 query 未恢复。真实远缘命中的初筛分数排名可能很低，需要几十甚至上百次重试才能命中；这会重新执行大部分原本希望省掉的 DP。

### 4.4 低置信度级联重试

仅在“完全无输出”时重试还会保留低质量错误结果，因此又加入 `trust_score`：没有输出，或当前最佳 `AS` 不超过该阈值时，继续重试，最多 100 个候选。四基因组同批 baseline 为 86.258 秒。

| Trust score | Wall time | 提速 | 丢失 query | 最佳分数下降 | 最佳位点改变 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 72.363 s | 1.192x | 0 | 26 | 54 |
| 50 | 84.198 s | 1.024x | 0 | 2 | 12 |
| 60 | 85.873 s | 1.004x | 0 | 0 | 0 |

`trust_score=60` 恢复了所有最佳分数和最佳位点，但只剩 0.4% 左右的 wall-time 改善。也就是说，恢复输出所需的重试工作量几乎正好吃掉全部初筛收益。

### 4.5 离线特征分析

为判断是否遗漏了更有效的廉价特征，实验在“全部候选放行”模式下记录候选特征，再与 baseline 输出关联。

- 282,018 个 rescue 候选中，有 1,858 个是某条 query 的最佳 rescue 命中。
- 其中 32 个最佳命中的初筛分数低于 30：mouse 6、rat 2、frog 15、zebrafish 9。
- baseline 共匹配到 8,309 条 rescue 输出记录，其中 1,016 条的初筛分数低于 30。
- 低分最佳命中的初筛分数范围为 18–29，初筛排名可低至第 99 名。
- 低分最佳命中的 DP 前 seed query 覆盖度最低只有 2.02%。

若要求不漏掉任何已观察到的最佳 rescue 命中，各单特征最多只能拒绝：

| 放行规则中的辅助信号 | 安全拒绝率 | 结论 |
| --- | ---: | --- |
| chain 分数 | 0.06% | 无区分力 |
| 无 gap 分数 | 0.55% | 无实际收益 |
| anchor 数 | 0.00% | 完全无区分力 |
| DP 前 seed 覆盖度 | 0.34% | 无实际收益 |
| 初筛排名 | 2.74% | 仍太小 |
| anchor 密度 | 9.81% | 只对最佳命中成立 |

最初曾观察到“最终 query 覆盖度不低于 10%”可安全拒绝约 15.94% 候选，但该覆盖度来自完整 DP 之后，不能用于 DP 前初筛。改为真正可用的 DP 前 seed 覆盖度后，安全拒绝率降至 0.34%。这是一次典型的数据泄漏，不能据此实现优化。

如果把要求从“保留最佳命中”提高到“保留全部 baseline 输出记录”，anchor 密度的安全拒绝率会从 9.81% 降到 2.69%，其他排名特征几乎全部降到 0%。

### 4.6 Anchor 密度端到端验证

离线分析只能证明某候选是否直接成为输出，不能证明删掉其他候选后全局排序、mask 和主次命中关系不变。因此又进行了严格端到端测试。规则为：初筛分数不低于 30，或 anchor 密度达到指定阈值时放行。

| 最小密度 | 实际拒绝率 | Wall time | 提速 | 丢失 query | 最佳位点改变 | 输出记录改变的 query |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 41 | 2.74% | 85.804 s | 1.058x | 0 | 12 | 76 |
| 80 | 6.70% | 83.165 s | 1.092x | 1 | 11 | 144 |
| 100 | 8.10% | 81.062 s | 1.120x | 4 | 15 | 166 |
| 120 | 9.18% | 79.332 s | 1.144x | 4 | 18 | 178 |
| 135 | 9.81% | 80.245 s | 1.131x | 4 | 17 | 189 |

同批 baseline 为 90.772 秒。即使最保守的密度 41 不丢 query、也不降低最佳 `AS`，四个基因组都无法得到字节级一致的 PAF，并有 76 条 query 的输出记录改变。密度达到 80 后开始丢失 query；密度 135 虽能拒绝约 9.8% 候选，但会丢失 4 条 query，并改变 189 条 query 的记录。

这一结果说明：即使一个候选自身最终不输出，它也可能通过排序、mask、parent/secondary 归类、fallback 或并列分数处理间接影响其他候选。离线“零假阴性”规则并不能保证端到端输出不变。

### 4.7 固定预算 mini-DP

最后测试了比无 gap BLOSUM 更接近正式 DP 的预判器：

- 每个候选最多取 2 个 anchor；
- 每个 anchor 分别执行左右 score-only、splice-aware SSE 延伸；
- nt flank 为 300，aa flank 为 24；
- 强制证据经过 anchor，不生成 CIGAR，也不调用 GPU。

离线阈值结果如下：

| 规则 | 保留对象 | 最大安全拒绝率 |
| --- | --- | ---: |
| `mini_dp >= 18` | 全部最佳命中和全部输出 | 0.51% |
| `pre >= 30 OR mini_dp >= 29 OR density >= 429` | 最佳命中 | 10.94% |
| `pre >= 30 OR mini_dp >= 34 OR density >= 45` | 全部输出 | 3.04% |

mini-DP 观测运行共执行 1,128,072 次小 DP，计算 9,583,019,859 个 cell，消耗 63.398 个累计线程秒。同期四基因组 `align_s` 合计为 3,890.261 个线程秒，因此 mini-DP 本身占约 1.63%。

在“保持全部输出”的规则下，理论上只拒绝 3.04% 候选，却先增加了 1.63% 的对齐阶段计算；考虑被拒候选成本并不均匀、分支和数据准备开销，以及端到端候选相互作用，预期净收益不超过约 1%，不值得继续增加实现复杂度。

## 5. 为什么初筛没有用

### 5.1 Rescue 集合存在天然选择偏差

容易识别的真实同源通常已有可信 anchor，不会进入 rescue 集合。进入初筛的候选本来就是 anchor 稀疏、跨度异常、重复干扰或进化距离较远的困难样本。因此，“局部分数低、anchor 少、覆盖窄”既是噪声候选的特征，也是 rescue 真阳性的共同特征。

### 5.2 真实弱同源与噪声在廉价特征上高度重叠

低分最佳命中包括 `IL10H_HCMVM`、`IL6_RABIT`、`IL10_CANLF`、`IL1B_PIG`、`IFNG_NUMME`、`OSTP_MOUSE`、`CSF2_CANLF`、`IL1B_HUMAN` 等免疫因子和细胞因子。它们的初筛分数可低至 18，排名可低至 99，seed 覆盖度可低至 2.02%。

这不是阈值略微不合适，而是分类边界本身缺失：把阈值调到能显著过滤噪声的位置，就会系统性删除本项目最希望保留的远缘弱同源。

### 5.3 排名和 query 级回退不能创造区分信息

固定保留前 K 个候选假设真命中排名靠前，但 K=4 仍丢 29 条 query。失败后重试可以逐步恢复结果，却必须尝试大量低分候选；当重试足以恢复最佳分数和位点时，提速只剩 1.004 倍。

回退机制只是把被推迟的 DP 重新执行一遍，并没有提高初筛的判别能力。

### 5.4 候选会通过全局选择逻辑相互影响

PAF 输出不是每个候选独立通过阈值后的简单并集。候选还参与排序、重叠 mask、primary/secondary 归类和 fallback。因而，删除一个最终未输出的候选，也可能改变另一候选的身份或输出条件。这解释了为何离线规则看似保留全部输出，端到端运行仍改变记录。

### 5.5 更强的预判器会侵蚀收益

mini-DP 加入剪接感知和局部动态规划后，安全拒绝率仍只有 0.51%–3.04%，但自身已消耗约 1.63% 的 `align_s`。继续增大窗口或 anchor 数会逐渐逼近正式 DP 的成本，失去“廉价初筛”的意义。

## 6. 最终决定

本轮假设在当前工作负载和输出稳定约束下已被证伪：

1. **不采用**无 gap BLOSUM 阈值作为 rescue 候选过滤器。
2. **不采用**chain 排名保留、query 失败重试或低置信度级联作为补救方案。
3. **不采用**anchor 密度、seed 覆盖度或 mini-DP 组合规则。
4. **不保留**相关 CLI 参数、运行时代码、profile 字段和临时测试，避免未验证功能进入 GitHub/Conda 发布版本。
5. **保留**生成的 benchmark 结果目录，作为否定结论和后续决策的实验依据。

这份结论不表示任何数据集上的初筛都绝对无效，而是说明：对于本项目关注的四个真实脊椎动物基因组、1,114 条蛋白，以及“保留弱同源和稳定输出”的目标，已测试的廉价局部特征没有足够判别力。若未来接受明确的有损模式，必须基于独立真值集重新定义目标，而不能把当前方案作为默认加速路径重新启用。

后续速度优化应优先选择不删除候选的方向，例如减少重复 DP、优化正式 DP 实现，或构造可证明不会淘汰潜在胜者的上界；不应继续围绕本报告已否定的 BLOSUM、chain、density 和 mini-DP 阈值做微调。
