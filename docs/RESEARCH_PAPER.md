# 从 miniprot 到 ProtLocus：一种以召回率为导向的蛋白质—基因组比对算法改进及其速度优化研究

日期：2026-09-10
代码基线：miniprot 0.18-r281（`miniprot_lh`）及其实验性分支 `ProtLocus`
测试环境：`Test_realdata` 数据集，1114 条蛋白 query × 4 个真实基因组（小鼠、大鼠、非洲爪蟾、斑马鱼），`-t56`

---

## 摘要

miniprot 是一种将蛋白质序列比对到基因组核酸序列的剪接感知（splice-aware）比对工具，采用"稀疏锚点(anchor)—链(chain)—动态规划(DP)拼接"的经典种子-延伸(seed-and-extend)范式。我们在原始实现（下称 `miniprot_lh`）基础上，针对其在重复序列/旁系同源基因密集的基因组上召回率不足的问题，构建了实验性分支 `ProtLocus`，引入了重复种子救援、按序列分组链接、放宽候选保留、无锚点候选救援 DP、可疑模型二次精修、综合排序六项机制，显著提升了召回率，但也带来了数倍的速度回退。本文系统性地：(1) 回顾 `miniprot_lh` 的原始算法设计作为相关工作背景；(2) 阐述 `ProtLocus` 各项改进的动机与实现，并给出通过插桩剖析定位性能瓶颈、设计速度优化的方法；(3) 在 4 个真实基因组、1114 条蛋白 query 的数据集上系统评测各项优化与对照实验。结果表明：无锚点候选的"救援"端点延伸 DP 占总比对时间的 95% 以上；跳过救援候选冗余二次重试的默认优化可在零精度回退下提速约 20%；按查询蛋白长度动态缩放端点延伸窗口的可选预设 `--fast` 可进一步提速约 24.7%（四基因组均值），仅 1 条 query 完全丢失；而直接照搬 `miniprot_lh` 的核心加速手段（丢弃无锚点候选、收紧候选保留范围）虽可获得 2.2×-7.3× 的速度提升，却要付出 10%-67% 的召回率代价。这说明"新算法的召回率收益"与"原算法的速度优势"是同一机制的一体两面，无法通过简单参数调节兼得，只能在两者之间选择合适的工作点。

## 1. 引言

### 1.1 研究背景

蛋白质—基因组比对（protein-to-genome alignment）是基因组注释、跨物种同源基因查找的基础工具之一。与核酸—核酸比对不同，蛋白质比对需要在基因组核酸序列上进行三联密码子翻译，并处理内含子剪接、移码、终止子等生物学现象，其比对搜索空间和动态规划复杂度显著更高。miniprot 通过"密集索引 + 稀疏锚点链接 + 局部精确重链 + 分段 DP 拼接"的多级过滤策略，在保证较高比对质量的同时把计算量控制在可接受范围内。

### 1.2 问题提出

在实际使用中我们发现，`miniprot_lh` 的默认策略——**没有可信锚点(trusted anchor)的候选区域一律直接丢弃，不做任何 DP** ——虽然带来了很高的速度，但在旁系同源基因、重复家族基因丰富的基因组（如两栖类、鱼类）上会系统性地漏检本应能找到的真实同源基因。为解决这一问题，我们在 `miniprot_lh` 基础上开发了 `ProtLocus` 分支（`--accuracy` 模式），核心改动是**不再丢弃无锚点候选，而是对其做一次全窗口"救援" DP**。这一改动显著提升了召回率，但也让比对阶段的计算量增加了数倍到十余倍，在实际大规模比对任务中速度已经"慢到不可接受"。

本文的问题是：**在已经为了召回率牺牲了速度的 `ProtLocus` 之上，能否在可控的精度代价下进一步提速？如果直接照搬 `miniprot_lh` 的加速手段，会付出怎样的代价？**

### 1.3 本文贡献

1. 系统梳理 `miniprot_lh` 的原始算法流程与 `ProtLocus` 六项召回率导向改进的动机与实现，明确二者速度差异的根本来源。
2. 通过插桩剖析，定量定位性能热点：**"救援"候选的端点延伸 DP 是唯一值得优化的目标**（占比对总时间的 95% 以上）。
3. 提出并验证一项**零精度回退**的默认优化（端点延伸二次重试跳过）与一项**精度换速度**的可选预设 `--fast`。
4. 实验性地把 `miniprot_lh` 的核心加速手段（丢弃无锚点候选、收紧候选保留范围）移植回 `ProtLocus`，用真实数据定量证明这类手段的速度收益与召回率代价，论证二者本质上的不可兼得性。

## 2. 相关工作：`miniprot_lh` 原始算法回顾

本节回顾本文的直接代码基线 `miniprot_lh` 的算法设计，作为后续方法与讨论的背景。

### 2.1 整体流程

```mermaid
flowchart LR
    A[基因组索引构建] --> B[粗略锚点/长程链 chain]
    B --> C[精确局部 5-mer 重链 refine]
    C --> D[分段拼接 DP 比对 mp_align]
    D --> E[候选过滤/排序 hit.c]
    E --> F[输出 PAF/GFF/GTF]
```

### 2.2 索引构建

基因组按 4 bit/碱基压缩存储；每条 contig 及其反向互补链分别按 3 个阅读框翻译为氨基酸序列，只保留不含终止子、长度 ≥30 aa 的开放阅读框（ORF）。氨基酸序列被约化为 13 组字母表后提取默认 6-mer，并按照哈希值最低 1 位为 0 的规则做 50% 的 modimer 二次采样，以减小索引体积、加速种子查找。相同位置去重后，以 256bp 定向区块 ID 的形式存储在稠密 CSR 数组中。

### 2.3 锚点编码与粗略链接（chain）

粗略锚点编码为 `block_id<<32 | query k-mer 结束位置（含）`；链接阶段采用类 minimap2 的链式 DP，使用分箱（binned）的间隙几何近似进行打分，同一区块内的锚点有额外奖励，并配合 max-skip / max-iter 启发式限制搜索规模。基因组侧的"内含子式"跳跃（target 端间距远大于 query 端）按 `min(线性罚分, 对数罚分)` 计算，鼓励发现真实的剪接结构而不过度惩罚长内含子。

### 2.4 精确局部重链（refine）

对粗略链覆盖的每个候选区域，重新提取**不做二次采样**（`mod_bit=0`）的精确 5-mer（保证局部灵敏度），并用**精确核酸偏移**重新编码锚点（`relative_nt_offset<<32 | query_offset`）。等哈希值的候选对做笛卡尔积匹配时设置 `max_ava=1000` 的上限以控制组合爆炸，之后用精确的 `3*dq - dr` 间隙几何重新执行链式 DP，保留每个候选区域内打分最高的局部链。

### 2.5 分段拼接 DP 比对（`mp_align`）：lh 速度优势的核心

这是本文最关心的部分。`mp_align` 对每个候选区域执行以下步骤：

1. **可信锚点检测**（`mp_filter_seed`）：在精链锚点中寻找一段"紧凑串"——连续 ≥3 个锚点、间距 ≤6 aa、基因组端阅读框一致。只有落在这样一段紧凑串内的锚点会被标记为"可信"（anchor 的最高位被置位）。
2. **关键判定分支**：
   ```c
   for (i = 0; i < r->cnt; ++i)
       if (r->a[i]>>31 & 1) break;
   if (i == r->cnt) {          // 一个可信锚点都没有
       r->cnt = 0;
       return;                //  直接丢弃，不做任何 DP
   }
   ```
   **这是 `miniprot_lh` 速度快的根本原因**：只要候选区域内找不到一段"紧凑串"锚点，无论该区域的粗略打分多高，都会被直接放弃，不消耗任何 DP 计算资源。
3. 对通过判定的候选，在可信锚点两端各执行一次**端点延伸 DP**（窗口大小由 `-e`/`max_ext` 与 `mp_cal_max_ext` 计算出的"到相邻候选区域的真实距离"共同决定，取较小者），再在锚点之间做窗口 DP 拼接，得到最终比对结果。
4. 候选保留策略同样保守：默认 `-N 30`（最多次优候选 30 个）、`-p 0.7`（次优候选打分需达主候选打分的 70% 以上才保留），比对前置阶段就已经把大量弱候选剔除，减少进入 `mp_align` 的候选总量。

### 2.6 候选过滤与排序

`hit.c` 负责将 DP 结果转换为最终区域坐标、按打分排序、依据 query 重叠区分主次比对（primary/secondary）、剪除冗余次优候选，并对多外显子结构给予适度优先，以缓解加工假基因（processed pseudogene）造成的误判。

### 2.7 `miniprot_lh` 的优势与局限

**优势**：由于绝大多数弱候选（尤其是重复序列/旁系同源区域产生的候选）在"可信锚点检测"这一步就被直接丢弃，`mp_align` 阶段实际执行的 DP 数量非常有限，整体速度很快。

**局限**：这一判定过于"一刀切"——很多**真实同源基因**，如果其比对区域恰好落在重复序列内、或者局部序列高度分化导致锚点稀疏分散，同样拿不到一段"紧凑串"，从而被误伤丢弃。这正是我们开发 `ProtLocus` 的直接动机。

## 3. 方法

### 3.1 `ProtLocus` 的设计：面向召回率的六项机制

#### 3.1.1 动机

在重复序列、旁系同源基因丰富的基因组（本文实验中的爪蟾、斑马鱼）上，实测显示 `--accuracy` 模式下高达 97.8%-98.2% 的候选区域在 `mp_filter_seed` 判定中"没有可信锚点"（详见 4.2 节）——这意味着如果沿用 `miniprot_lh` 的策略，这些候选会被全部丢弃。其中相当一部分实际上是可以被正确比对出来的真实基因，只是锚点碰巧稀疏/分散。

#### 3.1.2 六项机制

在 `miniprot_lh` 基础上，`--accuracy` 模式引入了以下六项机制（详见 `ACCURACY.md`）：

| # | 机制 | 作用 |
| --- | --- | --- |
| 1 | 重复种子救援 | 对被 `-c` 阈值过滤掉的重复 posting list，按比例均匀采样保留部分锚点（`--acc-repeat-cap`/`--acc-anchor-budget` 限流） |
| 2 | 按序列/链分组链接 | 粗链/重链阶段按 contig+链分区处理，避免跨结构错误合并 |
| 3 | 放宽候选保留 | `acc_best_n=100`（默认为 lh 的 30 的 3.3 倍）、`acc_pri_ratio=0.35`（默认为 lh 的 0.7 的一半），让更多、更弱的候选活到 DP 阶段去伪存真 |
| 4 | **无锚点候选救援 DP** | 不再丢弃无可信锚点的候选，而是标记 `rescued=1, full_dp=1`，对整个候选窗口执行一次全窗口 DP；仅用 `acc_rescue_cells` 做一个笼统的总 cell 数上限防止极端窗口 |
| 5 | 可疑模型二次精修 | 对含非典型剪接位点、移码、内部终止子或短插入的候选，做二次全窗口 DP 尝试替换（junc-refine），按综合打分决定是否采纳 |
| 6 | 综合排序 | 结合覆盖度、完整端点、剪接类型、移码、终止子等对候选重新打分，`--acc-rerank-margin` 限制加分幅度不能压过原始 DP 打分差距过大 |

其中第 4 项——**无锚点候选救援 DP**——正是与第 2 章"lh 速度优势核心"直接对立的改动：lh 在这里直接返回，accuracy 模式在这里反而开始做全窗口 DP。这一机制带来的召回率收益与速度代价将在第 4 章用实验定量给出。

### 3.2 性能剖析方法

为定位 `ProtLocus` 的性能瓶颈，我们在 `mp_align`/`map.c` 中插桩记录各阶段耗时与工作量计数器（`n_ext_calls`、`n_ext_cells`、`n_ext_retry`、`n_full_calls`、`n_full_cells`、`n_refine_pairs_dropped` 等），通过 `--profile` 输出，并在 4 个真实基因组、1114 条 query 的数据集上实测（`-t56`，线程秒累加）。所有插桩均通过"开关 `--profile` 前后 PAF 字节级一致"验证为无副作用，即插桩本身不影响比对结果。剖析结果见 4.2 节。

### 3.3 优化方法设计

#### 3.3.1 跳过 rescued 候选的端点延伸二次重试

**原理**：`miniprot` 的端点延伸 DP 在第一次窗口未能对齐到查询末端时，会用更宽松的罚分 `io_end`（19，替代默认 `io` 29）重新跑一次 DP，目的是照顾真正需要短末端外显子/内含子的情形。但对于本来就没有可信锚点、大概率是弱/错误候选的 `rescued` 类别，这次重试的价值存疑，且我们在剖析中发现该重试触发比例极高（见 4.2 节）。

**方法**：设计消融实验对比"全部跳过二次重试"与"仅对 `rescued` 候选跳过、真实可信锚点/强制全 DP 候选保留重试"两种方案，后者在 4 个基因组、1114 条 query 上使用严格 oracle（无终端延伸上限的比对结果）做召回率门禁验证，以确认是否存在精度回退。验证结果见 4.3 节。该优化最终作为默认行为上线，无需任何额外参数。

#### 3.3.2 `--fast`：按查询长度动态缩放端点延伸窗口

在 3.3.1 节优化后，端点延伸 DP 仍是绝对热点。既然大部分时间花在 `rescued` 候选的端点延伸窗口 DP 上，收紧该窗口的搜索范围即可继续降低成本，代价是窗口过小可能截断真实的长内含子/长末端外显子。

我们首先在核酸(nt)侧窗口上限（`--acc-end-ext`）与氨基酸(aa)侧窗口上限（`--acc-end-aa-cap`/`--acc-end-aa-ext`）两个维度做固定值参数扫描，选出速度与精度的最佳折衷点作为 `--fast` 的初版实现（4500nt / 800aa 固定窗口）。

固定窗口对所有 query 一视同仁，但数据集中蛋白长度差异极大（1114 条 query 长度中位数 187aa，第 90 百分位 391aa，最长 1332aa）：固定窗口对中位数附近的短 query 而言仍偏宽（浪费计算），对长尾的长 query 而言又可能偏窄（截断真实的长末端外显子）。为此我们进一步设计 `--acc-end-dyn` 选项，把 `rescued` 候选端点延伸的 nt 侧、aa 侧窗口上限从固定常数改为按当前 query 蛋白长度 `len` 线性缩放、并分别设有下限与上限（原 `--acc-end-ext`/`--acc-end-aa-ext` 退化为上限天花板）：

```
nt_cap = clamp(len * acc_end_nt_per_aa, acc_end_ext_min, acc_end_ext)   # 默认: len*15, 下限300, 上限10000
aa_cap = clamp(len * acc_end_aa_ratio,  acc_end_aa_min,  acc_end_aa_ext) # 默认: len*0.5, 下限50,  上限100000
```

我们在同一数据集上对比三种配置：`fast`（原固定 4500nt/800aa）、`dynA`（动态缩放，天花板保持默认不收紧）、`dynB`（动态缩放且天花板也收紧到 4500nt/800aa），以确定最终采纳哪一版作为 `--fast` 的实现。定量对比结果见 4.4 节。

#### 3.3.3 复现 `miniprot_lh` 加速手段的对照实验设计

为回答"能否直接照搬 lh 的做法进一步提速"这一问题，我们设计两组对照实验，直接在 `ProtLocus` 上复现 `miniprot_lh` 第 2 章描述的两个核心加速来源：

1. **完全复现"无锚点即丢弃"**（`--acc-no-rescue`）：关闭 3.1.2 节第 4 项机制，行为与 `miniprot_lh` 完全一致。
2. **折中复现"收紧候选保留范围"**（`--acc-best-n=30 --acc-pri-ratio=0.7`，救援机制保持开启）：只将候选保留宽松度（3.1.2 节第 3 项机制）从 accuracy 默认的 100/0.35 收紧回 lh 默认的 30/0.7，救援机制本身不关闭。

对于方案 2，我们额外设计了两项质量核查：(a) 以方案 1（`--acc-no-rescue`）为基准，统计方案 2 相对方案 1 新增比对上的蛋白数量（gained）与反而丢失的数量（lost），衡量"仅收紧候选保留、保留救援机制"相对"完全复现 lh"的净收益；(b) 以完整默认参数（含救援机制、无窗口收紧）的 baseline 为参照，逐条检查方案 2 新增比对上的蛋白是否也能被 baseline 独立找到，以排除收紧参数引入噪声候选的可能。两组实验及质量核查结果见 4.5 节。

## 4. 实验与结果

### 4.1 数据集与评价方法

- **数据集**：`Test_realdata/all_queries.fa`，1114 条真实蛋白序列，比对到 4 个真实基因组索引（小鼠、大鼠、爪蟾、斑马鱼）。
- **精度评价**：`Test_realdata/compare_recall.py`，对基线与候选方案的 PAF 输出按 query 取最高 `AS:i` 打分逐一比较，统计 `lost`（基线能比对、候选方案完全比对不上）、`gained`（反之）、`shared_worse`/`shared_better`（两边都能比对但分数变化）。
- **运行参数**：`-t56 --accuracy --profile`；已确认该数据集/配置下运行结果稳定可重复。
- **基线**：当前代码默认参数（已包含 4.3 节优化），即 `--acc-end-ext=10000 --acc-end-retry=89`（均为默认值，无需显式指定）。

### 4.2 性能瓶颈定位结果

- **`align_s`（比对阶段）占总线程时间的 95%-98%**，`refine_s`/`chain_s`/`sketch_s` 等阶段合计不足 5%。
- `align_s` 内部，**`align_ext_s`（可信锚点两端的"端点延伸" DP）占 95%-97%**；`align_gap_s`（锚点间拼接 DP）与 `align_full_s`（整窗救援/强制全 DP）各仅占 1%-2%。
- **91%-98% 的 `dp_candidate` 属于 `rescued`（无可信锚点）候选**（爪蟾 91454/93542=97.8%，斑马鱼 80887/82375=98.2%），即 3.1.2 节第 4 项机制新增的工作量。
- 进一步分析发现，`rescued` 候选的端点延伸 DP 中，**92.9% 会触发一次几乎同等代价的"二次重试"**（在第一次窗口未能对齐到查询末端时，用更宽松的罚分 `io_end` 再跑一次 DP）。

**根因结论**：性能瓶颈高度集中——不是拼接 DP，不是全窗救援 DP，不是精链或粗链阶段，而是"无锚点候选的端点延伸 DP 及其二次重试"，占了比对阶段绝大多数的计算时间。这为后续优化指明了唯一值得投入的靶点。

召回率方面，救援机制能够找回大量原本会被 `miniprot_lh` 直接丢弃的真实同源基因：4.5 节实验显示，关闭该机制后，爪蟾/斑马鱼分别有 61.9%/67.0% 的 query 完全丢失比对结果——反过来说，这正是救援机制"救回来"的召回率收益，与其 95% 以上的速度代价对应。

### 4.3 默认优化效果：跳过 rescued 候选的端点延伸二次重试

按 3.3.1 节设计的门禁实验验证，"仅对 `rescued` 候选跳过、真实可信锚点/强制全 DP 候选保留重试"方案在严格 oracle 召回率门禁下结果为 **`oracle_only=0`**（零回退）。

速度上，`align_ext_s` 降低 19%-36%，最终 3 次重复中位数 wall time 从 81.49s（4 基因组合计）降至 65.22s，提速约 **19.9%**，且相较于完全不设终端延伸上限的方案（158.29s）提速 **2.43 倍**。该优化现为默认行为，无需任何额外参数，是后续所有实验的基线。

## 5. 讨论

### 5.1 速度—精度权衡的本质

`miniprot_lh` 与 `ProtLocus` 在"无可信锚点候选"这一决策点上做出了完全相反的选择：前者丢弃（快、可能漏检），后者救援（慢、召回率高）。4.5 节的实验用真实数据定量证明：**只要恢复 lh 式的丢弃/收紧策略，就能获得 lh 级别的速度，但也会同比例地退回 lh 级别的召回率损失**——尤其是在重复序列/旁系同源基因丰富的基因组上（爪蟾、斑马鱼），因为这类基因组恰恰是"无锚点候选占比最高"（97.8%-98.2%）、也是"救援机制价值最大"的场景。这说明速度与召回率在这一机制上是同一枚硬币的两面，无法仅靠参数微调同时兼得两端的最优值；只能在两者之间选择一个可接受的工作点。

### 5.2 为什么 4.3/4.4 节的优化没有这个问题

4.3 节的优化跳过的是"救援候选内部"一次几乎重复的计算（二次重试），并非跳过救援本身，因此可以在不放弃救援机制"挽回真实候选"的核心价值的前提下消除冗余计算，这是它能做到零精度回退的原因。4.4 节的 `--fast`（无论固定窗口还是动态窗口）同样只收紧了救援候选的搜索窗口大小，而非取消救援资格，因此代价远小于 4.5 节两个方案（后者是从根本上减少了参与救援/被保留的候选数量）。

### 5.3 场景化建议

- **通用生产场景**：使用默认参数（已包含 4.3 节优化），零精度回退。
- **可接受少量、可控精度损失换取约 25% 整体提速**：使用 `--fast`（现为动态窗口实现，见 4.4 节）。
- **目标基因组重复序列极少、或后续流程会用其他方法补充结果、且能接受成倍的召回率损失**：可自行尝试 `--acc-no-rescue` 或 `--acc-best-n=30 --acc-pri-ratio=0.7`，但应先用真值数据验证，不建议未经验证直接用于生产。

## 6. 结论与未来工作

### 6.1 结论

本文从 `miniprot_lh` 的原始算法出发，系统梳理了 `ProtLocus` 分支为提升重复/旁系同源基因组召回率所做的六项改进，定量定位了改进带来的性能瓶颈（无锚点候选的端点延伸 DP 及其二次重试，占比对时间 95% 以上），并提出两级优化：一项零精度回退的默认优化（已上线，提速约 20%-36%/19.9%），以及一项精度换速度的可选预设 `--fast`（现按查询蛋白长度动态缩放端点延伸窗口，四基因组均值提速约 24.7%，仅 1 条 query 完全丢失，优于早期固定窗口版本的 3 条）。进一步地，我们通过直接复现 `miniprot_lh` 的核心加速手段，用真实数据定量证明了"新算法的召回率收益"与"原算法的速度优势"本质上互斥，为后续在这一方向上的任何参数调优划定了合理的期望边界。

### 6.2 未来工作

(1) 结合基因组重复序列注释信息，仅对确认位于非重复区域的候选保留完整救援窗口，对重复区域候选采用收紧策略，以期望在不牺牲爪蟾/斑马鱼这类基因组召回率的前提下进一步提速；(2) 探索候选级别的分层/两阶段 DP（先用廉价近似打分筛选，再对少数高潜力候选做完整救援 DP），以替代当前"全部救援候选一视同仁"的策略；(3) 对 `--acc-end-dyn` 的线性缩放系数（`acc_end_nt_per_aa`/`acc_end_aa_ratio`）做更细致的网格搜索或按基因组自适应调整，目前的默认值仅来自一轮参数扫描，仍有调优空间。
